> 适用场景：代码修改后的自检与测试；收尾检查；常驻服务实例只在服务器（<user> 账号）上运行

# 服务端运行铁律（最高优先级）
- **常驻/演示服务实例只允许在服务器 `<user>` 账号下运行（pm2 管理），严禁在本地启动常驻实例**
- 本地仅开发编写代码 + 静态自检；完整链路验证一律通过云端：SSH 到服务器看日志、curl 线上端口
- 服务器信息见 deploy-rules：`<user>@<SERVER_IP>`

# 自检（改完代码必做）
- Python：`python -m py_compile <file>`（逐个改动文件）+ 模块加载验证（`python -c "import <模块>"` 确认无导入错误）
- Node/TypeScript（如涉及）：`node --check <file>`（逐个改动文件）；TypeScript 改动以编辑器诊断面板 / `tsc --noEmit` 为准

# 测试（仅云端）
- 服务端改动 → SCP 上传到 <user> 账号（见 deploy-rules）→ 重启对应 PM2 服务 → curl 线上端口验证 + 看服务启动日志
- 功能验证走问数链路：自然语言提问 → 查询生成（过守卫）→ 执行 → 结构化卡片（表格/图表/结论）渲染正常
- 测试数据用完即删（临时记录、临时会话产物）

# 收尾（强制）
- `git status` 确认项目根与各子目录无临时文件残留（`tmp/` 内文件用完即删，**含密码的临时 SSH 脚本执行完立即删除**）
- 禁止把 `.env`（含令牌/连接串/API Key/密码）提交入库；密钥只存在于服务器侧 .env
