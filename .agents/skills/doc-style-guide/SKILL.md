# 文档写作风格规范 (Doc Style Guide)

## 核⼼理念

**代码优先，注释辅助，对比表替代长句，禁止事项 + 注意事项结尾。**

文档要让读者**看完代码示例就懂 80%**，正文只负责解释剩下 20%。

## 8 条写作手法

| # | 手法 | 说明 |
|---|------|------|
| 1 | **核心概念一句话** | 文档开头一句话点透这个工具/模块的设计理念 |
| 2 | **代码示例优先** | 每个 section 先给完整可运行的代码，再用 `//` 注释标注要点 |
| 3 | **参数说明内联** | 关键参数在代码中通过 `// 作用` 标注，不下沉到正文解释 |
| 4 | **对比表突出差异** | 两种方式的区别用 markdown 表格，不用段落描述 |
| 5 | **禁止事项 + 注意事项** | 末尾两段固定：❌ 禁止（短句粗体）+ 编号注意事项（1. 2. 3.） |
| 6 | **标题只到 ##** | 全文档最深层级是 `##`，扁平结构，不嵌套 |
| 7 | **短句不啰嗦** | 一句话能说清不写两句，能用 3 个例子的不写 5 个 |
| 8 | **类型零值速查** | 涉及类型的文档，一行列出所有类型的默认值 |

## 写作流程

```
确定文档类型（使用指南 / 规范说明 / 工作流）
    ↓
一句话写出"核心概念"
    ↓
按功能模块划分 section，每个 section 先写代码示例
    ↓
代码中用 // 注释标注关键参数
    ↓
两两对比处用 markdown 表格
    ↓
最后写"禁止事项"+"注意事项"
    ↓
自检：
  - 有没有一句话就能说清却用了两句话的？
  - 有没有可以用表格代替的段落描述？
```

## 风格对比示例

### ❌ 原风格（啰嗦式）

```
用户可以通过调用 query 方法来查询数据。query 方法接受两个参数，
第一个参数是 schema 名称，第二个参数是配置对象。配置对象中
可以设置 where 条件、params 参数、orderBy 排序等。如果
需要关联查询，可以在 include 中配置关系。
```

### ✅ 新风格（pg-store-usage 式）

```js
const items = await store.query('AuctionItem', {
  where: 'status = $1',    // SQL WHERE 片段
  params: ['ongoing'],      // 参数化查询值
  orderBy: 'start_time DESC',
  limit: 20,
  include: {
    bidders: {              // type: 'many' — json_agg 聚合
      orderBy: 'bid_time DESC',
      limit: 5,
    },
    creator: {},            // type: 'one' — 单条嵌入
  },
})
```

### ❌ 原风格（段落式对比）

```
在使用 upsert 功能时，如果条件匹配则更新现有记录，
如果条件不匹配则插入新记录。而 mutation 功能则
会自动判断 upsert 或 insert，并且支持父子文档的
关联填充。
```

### ✅ 新风格（对比表式）

| 方式 | 区别 |
|------|------|
| `upsert` | 需显式传 match 条件，不处理父子关系，仅单条 |
| `mutation` | 自动判断 upsert/insert，支持父子文档关联填充 |

## 禁止事项

❌ 不要在文档开头写大段背景介绍（读者只看怎么用）  
❌ 不要用段落描述参数含义（用代码注释或对比表）  
❌ 不要在文档中使用 `###` 及以上层级标题（保持扁平）  
❌ 不要把 `禁止事项` 和 `注意事项` 混在一起写（分两段）  
❌ 不要写超过 3 层的嵌套结构  

## 注意事项

1. **代码优先**：正文只补充代码示例说不清的 20% 信息，不要反客为主
2. **注释即文档**：`// 作用说明` 比正文更高效，读者扫一眼代码就懂
3. **表格代替段落**：凡涉及 A vs B 的比较，一律用 markdown 表格
4. **扁平结构**：全文档只用 `#` 和 `##`，不用 `###`，防止信息层级过深
5. **禁止事项排布**：❌ 后接短句粗体，每条不超过 15 字，一眼扫清
6. **数字编号顺序**：注意事项用数字编号，按重要性降序排列，不可乱序
7. **描述字段规则**：`description`（frontmatter）必须包含"做什么"和"何时调用"，控制在 200 字符内
