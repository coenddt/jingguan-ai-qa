# 日志详情增强：开发者完整排查

## Context（为什么做）

用户反馈：**日志详情的数据量太少**。日志是给开发人员看的，用于帮助开发人员解决问题，需要非常详细，不要错过任何细节。

现状问题（已核实）：
1. **前端 `QaDetailModal` 只渲染 AI 结论文本**：`web-front/src/features/qa/QaLogView.tsx` 的日志详情弹窗（L124-L199）对 AI 消息只显示 `m.content`（结论 Markdown），`aiMeta` 里的分析过程/数据发现/表格/统计/图表/追问全部未展示。
2. **后端 `aiMeta` 本身缺开发细节**：`server/app/services/qa_service.py` 的 `resp` 没有持久化：完整查询模板（`used_query` 只在 step desc 被 `[:180]` 截断）、LLM 原始产出（verify 前）、查询来源（精确缓存 vs LLM）、重试次数、是否截断、实际行数、实际使用的模型。

目标：日志详情弹窗成为开发者完整排查工具——完整复现 AI 回答全链路（分析过程 5 步真实中间产物、查询模板、LLM 原始产出、数据表格/统计/图表、结论、追问、原始 aiMeta JSON），历史老数据优雅降级。

## 改动清单

### 1. 后端 `server/app/services/qa_service.py`（`ask_stream`）

**新增变量**（现有 `tokens = 0` 附近初始化）：
```python
query_source = 'llm'            # 精确缓存命中后覆盖为 'exact_cache'
retries = 0                     # LLM 重试轮数（首轮通过为 0）
query_raw: dict | None = None   # LLM 最后产出的原始查询（verify 前）；缓存命中为 None
```

**赋值时机**：
- 精确缓存分支（`used_query = checked` 后）：`query_source = 'exact_cache'`
- LLM 首次生成（`invoke('query_gen', ...)` 后）：`query_raw = q`
- 重试循环内成功时：`retries = attempt`；重试 `invoke` 后：`query_raw = q`（始终记录最后一次 LLM 产出）

**resp 结构**（在 `resp` 构造前先建 `template`，供 resp 与 `query_cache.upsert` 共用）：
```python
# 完整校验后模板：聚合查询的 groupBy/measures 必须带上（日志完整展示 + 修复聚合缓存回放必失效）
template = {k: used_query[k] for k in ('model', 'mode', 'condition', 'fields', 'sort', 'limit',
                                       'groupBy', 'measures') if k in used_query}
resp = {
    'session_id': session['_id'],
    'steps': tracker.out(), 'findings': findings, 'columns': columns, 'rows': rows_2d,
    'stats': stats, 'chart': chart, 'text': text, 'follow_ups': follow_ups,
    'query': template,               # 新增：完整校验后查询模板
    'query_raw': query_raw,          # 新增：LLM 原始产出（缓存命中为 None）
    'query_source': query_source,    # 新增：'exact_cache' | 'llm'
    'retries': retries,              # 新增：重试轮数
    'truncated': truncated,          # 新增：是否被守卫截断
    'row_count': len(rows),          # 新增：实际执行返回行数
    'meta': {
        'elapsed_s': round(time.monotonic() - t0, 2),
        'tokens': tokens,
        'model': model_conf['name'],              # 新增：模型展示名
        'modelName': model_conf.get('modelName', ''),  # 新增：API 模型标识
        'platform': model_conf['platform'],       # 新增：平台 key
    },
}
```
- `template` 构造移到 `resp` 前；`query_cache.upsert(question, template, success=True)` 复用同一 `template`。
- 安全红线：`model_conf` 的 `apiKey/baseUrl` **禁止**写入 resp/落库，只取 `name/modelName/platform`。

### 2. 前端 `web-front/src/types.ts`

新增 `QaAskMeta`、`QaQueryTemplate` 接口，扩展 `QaAskResp`（新字段全可选，兼容历史数据）：
```ts
export interface QaAskMeta {
  elapsed_s: number; tokens: number
  model?: string; modelName?: string; platform?: string
}
export interface QaQueryTemplate {
  model: string; mode: 'query' | 'aggregate'
  condition: Record<string, unknown>; fields: string[]
  sort?: Record<string, number>; limit: number
  groupBy?: string[]; measures?: { op: string; field: string }[]
}
```
`QaAskResp` 新增：`query?: QaQueryTemplate`、`query_raw?: Record<string, unknown> | null`、`query_source?: 'exact_cache' | 'llm'`、`retries?: number`、`truncated?: boolean`、`row_count?: number`；`meta` 类型改为 `QaAskMeta`。

### 3. 前端新增 `web-front/src/features/qa/AiCard/qaBlocks.tsx`

从 `AiCard/index.tsx` 抽出 `Module`、`BlkPending`，并新增 `BlkEmpty`，供 AiCard 与 DevLogCard 共用（去重）。`AiCard/index.tsx` 改为 import 这三个组件，删除本地定义，行为不变。

### 4. 前端新增 `web-front/src/features/qa/DevLogCard.tsx`

开发者日志卡片，props `{ resp: Partial<QaAskResp> }`，复用块级子组件（`AiSteps`/`AiDataTable`/`AiStatsGrid`/`ChartView`/`MarkdownView`）与聊天页视觉一致，渲染顺序：
1. **分析过程**：`AiSteps`，默认展开（开发者视角）
2. **查询调试**（`Module`）：meta 行（来源/重试/截断/行数/耗时/Token/模型，缺失显示 `-`）+ 折叠的「查询模板（守卫校验后）」JSON + 折叠的「LLM 原始产出（verify 前）」JSON（缓存命中显示"精确缓存命中，未经过 LLM 生成"）
3. **数据发现**、**数据表格**（`AiDataTable`，`totalCount` 取 `row_count`）、**数据统计**（`AiStatsGrid`）、**数据可视化**（`ChartView`）、**结论**（`MarkdownView`）
4. **追问建议**：纯文本 chips（`fu-chip fu-chip-static`，不可点击，不触发问数）
5. **原始日志**：`<details>` 折叠区，`JSON.stringify(resp, null, 2)` + 复制按钮（复用 `services/clipboard.ts` 的 `copyToClipboard`）

防御性渲染：所有新字段可选；aiMeta 空对象由外层兜底纯文本气泡。

### 5. 前端 `web-front/src/features/qa/QaLogView.tsx`

- import `DevLogCard`；AI 消息分支改为：`m.aiMeta` 有内容时渲染 `<DevLogCard resp={m.aiMeta} />`，否则保留现有纯文本气泡兜底。
- Modal `boxClassName` `max-w-3xl` → `max-w-4xl`，滚动区 `max-h-[60vh]` → `max-h-[70vh]`（容纳 JSON 代码区）。

### 6. 前端 `web-front/src/index.css`

在日志视图样式区块新增开发者卡片样式：`dev-meta-grid`（meta 行）、`dev-details`（折叠标题）、`dev-pre`（深色 JSON 代码区，`max-height:320px; overflow:auto; word-break:break-all`）、`dev-copy-btn`、`fu-chip-static`。

## 不改动的文件（已确认）

- `server/app/routers/qa.py`：`list_messages` 已全量返回 aiMeta。
- `server/app/models/schema/qa_message.py`：`aiMeta` 为自由 object，可直接落库新字段。
- `web-front/src/hooks/useQaChat.ts`：done 事件整体替换 aiMeta，新字段纯增量。
- 聊天页 `AiCard`：保持面向业务的简洁卡片，不展示调试信息（调试信息只属日志详情）。

## 边界与兼容性

- 老数据缺新字段：全部按可选渲染（显示 `-` 或隐藏区域），不报错。
- 精确缓存路径：`query_raw=null`、`query_source='exact_cache'`、`retries=0`；缓存命中但守卫失败回退 LLM 时 `query_source` 保持 `'llm'`（语义正确）。
- `template` 补齐 `groupBy/measures` 后：聚合问法可真正命中精确缓存（此前必回退 LLM），属行为改进；老缓存数据缺字段仍会走守卫失败回退，无需迁移。
- 超大表格：rows 上限 200，JSON 区 `max-height` 防撑爆弹窗。
