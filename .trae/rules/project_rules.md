# 基调思想

> **让数据问答对话可及——自然语言进，text-to-query 出，结果直观可见。**

- 此为本项目最高级别规则，优先级高于其他一切分领域规则

- 一切功能设计、交互流程、文案取舍，都服务于"用户在聊天框提问，AI 自动选模型、生成查询（text-to-query）、执行取数，并以结构化卡片（分析过程 + 数据发现 + 表格 + 统计 + 图表 + 追问建议）回答"这一目的，而非堆砌技术演示

- 演示是生命线：智能问数链路（选模型 → 生成查询 → 执行 → 图表/结论，分析过程 5 步真实中间产物）必须端到端可演示，禁止半成品

- 数据可信是底线：text-to-query 数据自制（8 张业务表：3 台账 + 5 统计报表，维度值以原型为准），LLM 产出的查询一律先过守卫校验（只读 + 白名单 + 行数上限）再执行，禁裸管道直通

> 术语注：v2.0 起"text-to-query"指 LLM 产出对 mongo-store-py 模型的结构化查询（模型名 + 条件 + 聚合模板），非 SQL 文本；早先文档/口语中的"text2sql/SQL"表述一律按此理解。

- 技术实现是仆从：任何技术方案若与此基调冲突，以此基调为准重新权衡

# 自动反馈原则（告警优先——纵深防御的征兆闭环）

> **防护被击穿是上游出错的征兆；比防护本身更重要的是告警，告警即自动反馈，指引 AI 回溯加固。**

- 堡垒思想：系统采用纵深防御（外层防护罩、内层防护罩、核心防护罩）。某层防护被穿透、却在下一层被挡下，系统表面上无恙，但已出现"上一步出错"的征兆。此时最重要的不是庆幸防护挡住，而是**告警**——没有告警就无法知道该加固哪一层。

- 自动反馈是告警的载体：任何兜底、越界、防护拦截一旦触发，都必须自动产出一条反馈，写明**触发原因、命中哪一层防护、上一步哪里出了问题、如何修复**，供 AI 工具（或人）复制后直接探查与修复。此反馈称为自动反馈。

- 触发范围（三类必须反馈，缺一不可）：

  - **守卫校验拦截**：text-to-query 守卫（只读 / 白名单 / 行数上限）拦截路径——拦截只证明保护到位，真正的病灶在上游 LLM 产出的查询，必须反馈该查询为何越界；

  - **兜底 / 降级逻辑**：模型选型失败降级、默认值兜底、异常回退等路径被走到，说明主路径有问题，必须反馈走了哪条兜底、正常路径为何失效；

  - **越界 / 异常输入**：超范围请求、参数越界、非法维度值等被护栏挡下时，必须反馈输入为何不合法、应如何修正。

- 原则：**允许被拦截，禁止静默失守**。任何一种防护触发都可以发生（保护到位），但不允许"发生了却无人知"（静默）。宁可误告警，不可漏告警。

- 技术实现是仆从：任何技术方案若与此原则冲突，以此原则为准重新权衡。
