# 核心理念

**分层自检：L1 保"能跑"，L2 保"可证"；评分先过否决，再算加权。**

# L1 一般自检（每次改码必做，秒级）

```bash
python -m py_compile <改动文件>    # 语法编译，逐个改动文件
python -c "import <模块>"          # 模块加载，暴露缺依赖/循环导入
pytest -x -q                      # 快速回归，首错即停（仅纯函数用例）
ruff check .                      # 风格 + 静态违规
black --check .                   # 格式一致性
```

- 最小集（py_compile + import）已内嵌 testing-rules（alwaysApply），本规则是其扩展
- pytest 仅跑不依赖服务启动的纯函数用例；联网链路验证一律走云端（见 testing-rules）

# L2 极致自检（合码/发版前，分钟级）

| 检查项 | 命令 | 阈值 |
|---|---|---|
| 严格类型 | `mypy --strict app` | 零报错 |
| 静态评分 | `pylint app` | ≥ 9.0 |
| 测试覆盖率 | `pytest --cov=app --cov-branch` | ≥ 90%（行 + 分支） |
| 代码漏洞 | `bandit -r app -ll` | 零高危 |
| 依赖 CVE | `pip-audit` | 零高危 |
| 圈复杂度 | `radon cc app -s` | ≤ 10 |
| 死代码 | `vulture app` | 零（误报人工确认后白名单） |
| 变异测试 | `mutmut run` | 存活突变 ≤ 10% |

- 逐条执行，任一非零退出即拦截，不继续往下跑

# 评分卡（100 分制）

先跑否决项，任一命中总分记 0，不再算加权：

- **一票否决**：编译失败 / 导入失败 / 核心用例红 / 高危漏洞（bandit 或 pip-audit）

| 维度 | 构成 | 分值 |
|---|---|---|
| 正确性底线（否决） | 编译 10 · 导入 10 · 单测 10 | 30 |
| 测试质量 | 覆盖率 15（≥90% 满分，线性折算）· 变异得分 10 | 25 |
| 静态质量 | pylint ≥9.0 得 12 · ruff 零违规 8 | 20 |
| 类型安全 | mypy --strict 零报错 | 10 |
| 安全扫描 | 基础 10 分，高危 −10/个 · 中危 −2/个（下限 0） | 10 |
| 可维护性 | 圈复杂度达标 3 · 无死代码 2 | 5 |

| 等级 | 分数 | 处置 |
|---|---|---|
| A | ≥ 90 | 可部署上线（SCP + PM2） |
| B | 80–89 | 可合入 |
| C | 70–79 | 修复后重审 |
| D | < 70 | 打回重写 |

# 门禁优先（阈值交给工具）

```bash
pylint app --fail-under=9.0                              # 低于 9.0 → exit 1
pytest --cov=app --cov-branch --cov-fail-under=90 -q     # 覆盖率 < 90% → exit 1
bandit -r app -ll -q                                     # 出现高危 → exit 1
```

- 门禁版优先：让工具自己 exit 1，人只看过/不过，不被分数绕过
- 极简版：直接拿 pylint 10 分制当总分（≥9.0 放行），它已综合规范/复杂度/潜在 bug
- 评分版适用场景：多模块横向对比、质量趋势跟踪（看分数波动）

# 禁止事项

❌ **否决项未过就算分**
❌ **为凑覆盖率写空测试**
❌ **本地起常驻服务跑自检**
❌ **门禁拦截不留告警**
❌ **跳过 L1 直接上 L2**

# 注意事项

1. **权重按项目调**：金融/安全类项目把"安全扫描"提到 25 分
2. **分数看波动**：突降 10 分比绝对低分更有信息量，优先查最近改动
3. **告警即反馈**：任一门禁/防护触发，自动产出反馈（触发原因、命中哪层、如何修复），禁止静默——见自动反馈原则
4. **变异测试慢**：只对核心模块（守卫、执行器、text-to-query 生成）跑，不跑全量
5. **工具未装先补齐**：ruff / black / mypy / pylint / pytest-cov / bandit / pip-audit / radon / vulture / mutmut 加入 dev 依赖
6. **上线门槛**：部署到 <user> 服务器前必须 A 级（≥90）且否决项为零
