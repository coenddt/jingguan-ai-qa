# Chat 对话式交互测试用例文档生成器

## 核心概念

生成覆盖 SSE 流式协议、意图识别、上下文指示器、长按菜单、多轮对话、卡片渲染、角色权限、边界异常 8 个维度的标准化测试用例文档。存入 `doc/test-case/<YYYY>/<MM>/`。

## 文档状态生命周期（文件名前缀 = 文档级状态）

文件名前缀随文档进度推进，便于扫目录一眼看出进度、中断后定位续做：

| 阶段 | 文件名前缀 | 何时 |
|---|---|---|
| 未处理 | `未处理-<主题>.md` | 文档刚创建，尚未开始 |
| 处理中 | `处理中-<主题>.md` | 开始处理/编写时重命名 |
| 已完成 | `已完成-<主题>.md` | 全部完成时重命名 |

状态迁移规则：
- 开始处理 → 文件名前缀改 `处理中-`
- 全部完成 → 文件名前缀改 `已完成-`
- 中断续做：重新打开文档，从上次进度继续，已完成内容不重做

> 改名仅人工约定，**无任何脚本/流程依赖文件名**，可放心改名（各文档生成 skill 统一约定）。

## 按需加载（决策树）

正文只保留总览、状态约定、账号、流程与红线约束，实现细节按需读取 `subs/` 子文件：

| 场景 | 读取文件 |
|------|---------|
| 目录结构 / 文档头模板 / 测试用例格式 | [subs/template.md](subs/template.md) |
| 测试维度 1-4（SSE / 意图 / 上下文指示器 / 长按菜单） | [subs/dimensions-1-4.md](subs/dimensions-1-4.md) |
| 测试维度 5-8（多轮 / 卡片 / 角色 / 边界异常） | [subs/dimensions-5-8.md](subs/dimensions-5-8.md) |

## 测试账号准备

| 账号 | 角色 | 说明 |
|------|------|------|
| test_user_01 | 普通用户 | 已注册未实名 |
| test_user_vip | 实名用户 | 已通过实名验证 |
| test_admin | 管理员 | 拥有管理权限 |

## 使用流程

1. **确定范围**：明确需要测试的对话交互功能模块
2. **选择维度**：从 8 个维度中选择需要覆盖的维度
3. **创建目录**：确保 `doc/test-case/<YYYY>/<MM>/` 目录存在
4. **编写用例**：按上述格式逐条编写
5. **评审用例**：检查覆盖率、优先级分配
6. **执行测试**：在微信开发者工具 + 云服务器中执行
7. **记录结果**：标注通过/失败/阻塞状态
8. **失败诊断**：调用 `bug-console` 技能收集证据

## 关联技能

- `bug-console` — 测试失败时收集运行时证据

## 禁止事项

❌ 禁止用例描述中使用技术实现细节（不写 "SSE EventSource 的 onmessage 回调"）  
❌ 禁止缺少预期结果（每个测试步骤必须有对应预期）  
❌ 禁止所有用例都是 P0（区分 P0/P1/P2 优先级）  
❌ 禁止不写验证方式（必须明确如何验证）  

## 注意事项

1. **P0 优先级**：核心功能冒烟测试，失败即阻断发版；P1 为重要功能，P2 为边缘场景
2. **测试数据预设**：至少预设 5+ 个测试标的（不同类型如北京房产、上海股权），3+ 个用户发布标的
3. **验证方式多样化**：人工判断回复质量需结合 Network 面板和服务端日志交叉验证
4. **测试用例模板复用**：8 个维度的模板可直接复制使用，替换测试数据即可
5. **文档目录自动创建**：写入前确保 `doc/test-case/<YYYY>/<MM>/` 目录存在，不存在则创建
