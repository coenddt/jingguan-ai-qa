# 测试维度 1-4（SSE / 意图识别 / 上下文指示器 / 长按菜单）

## 1. SSE 流式协议（SSE）

| 子类 | 重点 |
|------|------|
| SSE-01~10 | 基础流式：正常连接、逐字输出、DONE 事件、content 非空 |
| SSE-11~20 | 中断与恢复：网络断开、页面切换、重连后继续 |
| SSE-21~30 | 超时与错误：服务端超时、ERROR 事件、空响应 |

```markdown
### TC-SSE-01：正常 SSE 流式响应

| **测试ID** | TC-SSE-01 |
| **优先级** | P0 |
| **前置条件** | 用户已登录，进入 chat 页面 |
| **测试步骤** | 1. 输入普通文本消息\n2. 点击发送\n3. 观察消息区域 |
| **预期结果** | 1. SSE 连接建立（Network 可见 events）\n2. AI 回复逐字渐显，无卡顿\n3. 流结束后触发 DONE 事件\n4. content 非空且相关 |
| **验证方式** | Network 面板 + 前端渲染观察 |

### TC-SSE-02：SSE 流中断后重连

| **测试ID** | TC-SSE-02 | **优先级** | P1 |
| **前置条件** | 用户已登录，正在接收 SSE 回复 |
| **测试步骤** | 1. 发送消息\n2. AI 回复中模拟网络断开（DevTools Offline）\n3. 恢复网络 |
| **预期结果** | 1. 中断时有 loading/断线提示\n2. 恢复后自动重连或可手动重试\n3. 已有内容不丢失\n4. 最终获完整回复 |

### TC-SSE-03：SSE 空响应处理

| **测试ID** | TC-SSE-03 | **优先级** | P1 |
| **前置条件** | 用户已登录 |
| **测试步骤** | 1. 构造 LLM 返回空 content 的请求\n2. 发送消息 |
| **预期结果** | 1. SSE 正常完成（DONE 事件）\n2. content 为空时展示友好提示\n3. 不出现白屏/崩溃 |
```

## 2. 意图识别（INT）

| 子类 | 重点 |
|------|------|
| INT-01~10 | 意图分类：搜索/闲聊/功能意图判定准确性 |
| INT-11~20 | 子意图引导：SEARCH 后的 due_diligence/bid_analysis 建议 |
| INT-21~30 | 降级处理：不支持某意图时的 fallback |

```markdown
### TC-INT-01：搜标意图识别

| **测试ID** | TC-INT-01 | **优先级** | P0 |
| **前置条件** | 用户已登录，进入 chat 页面 |
| **测试步骤** | 1. 输入搜标关键词（如"北京房产拍卖"）\n2. 点击发送\n3. 检查 SSE 响应中的 intent 字段\n4. 检查前端引导展示 |
| **预期结果** | 1. intent 正确识别为 `asset_search`\n2. 搜索结果展示标的卡片\n3. 消息下方展示子意图引导条 |
| **验证方式** | Network 面板 + 前端渲染 |
```

## 3. 上下文指示器（CTX）

| 子类 | 重点 |
|------|------|
| CTX-01~05 | 默认状态：进入 chat 默认「全网搜标」 |
| CTX-06~10 | 切换逻辑：从长按菜单/底部功能触发 |
| CTX-11~15 | 参数透传：切换后发消息携带正确 API 参数 |
| CTX-16~20 | 清除逻辑：发送后/手动关闭后恢复默认 |

```markdown
### TC-CTX-01：默认上下文指示器

| **测试ID** | TC-CTX-01 | **优先级** | P0 |
| **前置条件** | 用户已登录，未选择任何功能 |
| **测试步骤** | 1. 进入 chat 页面\n2. 观察输入框上方区域 |
| **预期结果** | 1. 显示「全网搜标」\n2. 轻量提示样式（非选中高亮态）\n3. placeholder 显示搜标相关提示 |

### TC-CTX-02：通过长按菜单切换上下文

| **测试ID** | TC-CTX-02 | **优先级** | P1 |
| **前置条件** | 有一条关联标的的 AI 回复消息 |
| **测试步骤** | 1. 长按关联标的的 AI 回复\n2. 弹出菜单中选择「标的尽调」\n3. 观察指示器变化\n4. 输入文本发送\n5. 检查 API 请求参数 |
| **预期结果** | 1. 指示器更新为「标的尽调：{标的名称}」\n2. API 请求携带 `actionContext: 'due_diligence'` 和 `auctionItemId`\n3. 发送后指示器恢复默认 |
```

## 4. 长按菜单（MENU）

| 子类 | 重点 |
|------|------|
| MENU-01~05 | 菜单可见性：普通文本 vs 关联标的 vs 自己标的 vs 他人标的 |
| MENU-06~10 | 功能入口：查看详情、标的尽调、出价分析、AI修改 |
| MENU-11~15 | 角色差异：非实名用户看不到「出价分析」 |

```markdown
### TC-MENU-01：关联标的的消息长按菜单

| **测试ID** | TC-MENU-01 | **优先级** | P0 |
| **前置条件** | 有一条关联标的的 AI 回复 |
| **测试步骤** | 1. 长按关联标的的消息\n2. 观察菜单选项 |
| **预期结果** | 1. 包含「查看详情」\n2. 包含「标的尽调」\n3. 已实名用户包含「出价分析」\n4. 用户发布的标的包含「AI修改」\n5. 不含「复制」 |

### TC-MENU-02：普通文本消息长按菜单

| **测试ID** | TC-MENU-02 | **优先级** | P1 |
| **前置条件** | 有一条纯文本 AI 回复（无标的关联） |
| **测试步骤** | 1. 长按纯文本消息\n2. 观察菜单选项 |
| **预期结果** | 1. 仅包含「复制」\n2. 不显示标的相关操作入口 |
```
