# Web 前端极致自检规范

## 核心概念

一句话：**自检不是"我觉得没问题"，而是每个分数都有可复现证据——机器能测的进 CI，人只走查机器测不了的。**

**适用目录**：`web-front/`
**适用时机**：代码交付前、版本发布前、阶段验收前
**浏览器基准**：Chrome / Edge 最新版 + 移动端 375px 断点

## 两层自检体系

| 层级 | 目标 | 方式 |
|------|------|------|
| L1 基础自检 | 保正确——有没有做对 | 人工走查 checklist |
| L2 极致自检 | 保质量——用指标证明做好了 | 工具度量 + 证据留存 |

L1 必过，不做评分；L2 按本文评分模型打分定级。

## 评分模型

```
总分 = Σ(维度得分 × 权重)    // 满分 5.0
```

| 维度 | 权重 | 证据来源 |
|------|------|----------|
| 功能正确性 | 25% | 走查录屏、边界清单 |
| 性能 | 15% | Lighthouse、bundle 分析、Performance 录制 |
| 安全 | 15% | npm audit、注入面走查、网络面板 |
| 健壮性 | 10% | DevTools 弱网模拟、异常注入 |
| 代码质量 | 10% | ESLint / tsc 输出、重复率扫描 |
| 可测试性 | 10% | 覆盖率报告、E2E 运行记录 |
| 交互体验 | 10% | 多端录屏、操作路径计时 |
| 可访问性 | 5% | axe / Lighthouse 扫描、键盘走查 |

## 通用评分锚点

| 分值 | 定义 |
|------|------|
| 0 | 未检查且无证据 |
| 1 | 有阻断性问题 |
| 2 | 明显缺陷 |
| 3 | 达标且有证据 |
| 4 | 良好并覆盖部分极致项 |
| 5 | 卓越且证据完备 |

**无证据，任何维度上限 3 分。**

## 各维度评分标准

**1. 功能正确性 · 25%**

| 分值 | 标准 |
|------|------|
| 5 | 主流程 + 边界 + 三态（加载/空/错）全覆盖；竞态、重复提交、token 并发刷新均已验证 |
| 4 | 主流程与常见边界覆盖，三态完备，长尾场景（超长文本/特殊字符/时区）仅抽验 |
| 3 | 主流程通过，三态基本完备，边界抽样 |
| 2 | 存在未处理的空态/错误态，或分页末页、筛选组合等边界出错 |
| 1 | 主流程存在阻断性 bug |

**2. 性能 · 15%**

| 分值 | 标准 |
|------|------|
| 5 | LCP<2.5s、INP<200ms、CLS<0.1；路由级 + 重组件懒加载；长列表虚拟化；10 分钟内存平稳无泄漏；bundle 预算进 CI |
| 4 | 三指标达标，分包完成，仅剩少量优化空间（图片格式/预加载） |
| 3 | 指标达标但无懒加载等主动优化 |
| 2 | 单项超标（如 INP>500ms）或首屏 >4s |
| 1 | 两项以上 Core Web Vitals 超标 |

**3. 安全 · 15%（≤1 分触发一票否决）**

| 分值 | 标准 |
|------|------|
| 5 | 零 eval / 裸 innerHTML，HTML 注入点全过 DOMPurify；token 过期 + 刷新机制；audit 零高危；越权走查通过；零硬编码密钥 |
| 4 | 基本面全覆盖，仅剩低危提示项 |
| 3 | XSS 注入面已查，但依赖未审计或密钥管理不完整 |
| 2 | 高危依赖未处理，或敏感信息硬编码 |
| 1 | 存在可利用 XSS / 接口越权（直接判 D） |

**4. 健壮性 · 10%**

| 分值 | 标准 |
|------|------|
| 5 | 断网/弱网有降级；请求超时 + AbortController 取消；失败重试幂等；ErrorBoundary + 拦截器全局兜底 |
| 4 | 断网/超时有处理，个别路径缺自动重试 |
| 3 | 请求失败有统一提示，无自动重试 |
| 2 | 接口异常导致白屏或无任何提示 |
| 1 | 异常引发页面崩溃 |

**5. 代码质量 · 10%（子检查项以 web-front-01~11 规范为准）**

| 分值 | 标准 |
|------|------|
| 5 | lint / tsc 零 error 零 warning；重复率 <1%；组件 <300 行；无 any 滥用；命名语义化；01~11 规范逐条通过 |
| 4 | 零 error，少量 warning 已评估留痕 |
| 3 | 零 error，存在记录在案的技术债 |
| 2 | eslint-disable 滥用或 error 被忽略 |
| 1 | 类型断言普遍绕过检查 |

**6. 可测试性 · 10%**

| 分值 | 标准 |
|------|------|
| 5 | 关键路径 E2E 覆盖；工具函数/核心逻辑单测覆盖率 ≥80%；无 flaky 用例；覆盖率进 CI 卡口 |
| 4 | 核心逻辑有单测，E2E 覆盖主流程 |
| 3 | 手工用例文档完整，自动化部分覆盖 |
| 2 | 仅临时手工测试，无用例记录 |
| 1 | 无任何测试 |

**7. 交互体验 · 10%**

| 分值 | 标准 |
|------|------|
| 5 | 骨架屏/乐观更新；操作视觉反馈 <100ms；防抖节流到位；按钮防重 + loading 态；表单即时校验且文案明确；危险操作二次确认 |
| 4 | 反馈及时，主操作有 loading，个别细节缺失 |
| 3 | 有 spinner/提示，无骨架屏 |
| 2 | 操作无反馈或反馈明显延迟 |
| 1 | 点击无响应且无任何提示 |

**8. 可访问性 · 5%**

| 分值 | 标准 |
|------|------|
| 5 | 全键盘可达且焦点可见；对比度 ≥4.5:1；表单 label/图片 alt 齐备；axe 扫描零严重问题；遵循 prefers-reduced-motion |
| 4 | 键盘 + 对比度达标，个别 ARIA 属性缺失 |
| 3 | 主流程键盘可操作，存在焦点丢失 |
| 2 | 交互强依赖鼠标，键盘不可用 |
| 1 | 文字对比度严重不足 |

## 定级与一票否决

| 级别 | 总分 | 结论 |
|------|------|------|
| A | ≥ 4.5 | 卓越，可发布 |
| B | ≥ 3.5 | 合格，可发布 |
| C | ≥ 2.5 | 待改进 |
| D | < 2.5 | 需重构 |

**一票否决（不进加权，直接 D）**：

❌ 安全维度 ≤1 分（可利用 XSS / 接口越权）
❌ 展示错误数据
❌ 主流程白屏或崩溃

## 执行流程

```
1. 查否决项 → 命中直接判 D，结束
2. 分维打分 → 每维附证据（报告链接/录屏/lint 输出）
3. 加权求和 → 得总分
4. 定级     → 记录到自检报告
```

## 计分示例

```
功能4×0.25 + 性能5×0.15 + 安全5×0.15 + 健壮4×0.10
+ 代码3×0.10 + 测试3×0.10 + 体验4×0.10 + a11y4×0.05
= 1.00 + 0.75 + 0.75 + 0.40 + 0.30 + 0.30 + 0.40 + 0.20
= 4.10 → B 级
```

## CI 自动化卡口

```bash
npm run build                      # 已有：tsc --noEmit + vite build（类型 + 构建卡口）
npm audit --audit-level=high       # 安全卡口：高危依赖即 fail
npx eslint . --max-warnings 0      # 待建：代码质量卡口
npx vitest run --coverage          # 待建：覆盖率卡口（阈值 80%）
```

| 卡口 | 状态 | 失败处理 |
|------|------|----------|
| tsc --noEmit | 已有（build 内） | 阻断发布 |
| npm audit 高危 | 可直接接入 | 升级依赖或评估留痕 |
| ESLint | 待配置 | 配置后阻断发布 |
| 覆盖率 ≥80% | 待建测试体系 | 建成后阻断发布 |

## 自检报告模板

```markdown
# 自检报告 · YYYY-MM-DD

| 维度 | 得分 | 证据 |
|------|------|------|
| 功能正确性 | 4 | 走查录屏 tmp/walkthrough.mp4 |
| 性能 | 5 | Lighthouse 报告 tmp/lh.html |
| 安全 | 5 | audit 输出 + 注入面清单 |
| 健壮性 | 4 | 弱网录屏 |
| 代码质量 | 3 | tsc 零 error，warning 2 条已留痕 |
| 可测试性 | 3 | 手工用例文档 doc/test-case/ |
| 交互体验 | 4 | 多端录屏 |
| 可访问性 | 4 | axe 扫描截图 |

总分：4.10　级别：B　否决项：无
遗留问题：xxx（负责人 / 期限）
```

报告存 `doc/test-report/YYYY/MM/`。

## 禁止事项

❌ **无证据打分**
❌ **主观拍脑袋定级**
❌ **否决项进加权计算**
❌ **绕过 CI 卡口发布**
❌ **报告只写结论不写证据**
❌ **测试数据长期残留**

## 注意事项

1. 先查否决项，再分维打分；否决项命中即结束，不进加权
2. 机器能测的（lint / tsc / audit / 覆盖率）进 CI 自动卡口，人工只走查交互、文案、视觉一致性
3. 无证据任何维度上限 3 分；证据必须可复现（报告 / 录屏 / 命令输出）
4. 代码质量维度子检查项以 `.trae/rules/web-front-01~11` 规范逐条展开为准
5. 临时录屏、报告等测试产物用完即删，正式报告归档 `doc/test-report/YYYY/MM/`
6. 性能指标以 Lighthouse 移动端模拟为准，桌面数据仅作参考
