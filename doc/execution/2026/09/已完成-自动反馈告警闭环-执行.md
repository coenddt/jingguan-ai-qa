## 4. 详细执行契约（代码优先）

### 4.1 AutoFeedback schema

```python
# server/app/models/schema/auto_feedback.py
AUTO_FEEDBACK_SCHEMA = {
    'name': 'AutoFeedback', 'collection': 'auto_feedback',
    'idPrefix': 'AF', 'timestamps': True,
    'fields': {
        'category':     {'type': 'string', 'default': 'guard'},  # guard / fallback / input
        'triggerPoint': {'type': 'string', 'default': ''},        # 命中点标识
        'reason':       {'type': 'string', 'default': ''},        # 触发原因（GuardError 原文）
        'layer':        {'type': 'string', 'default': ''},        # 命中哪层防护
        'upstream':     {'type': 'string', 'default': ''},        # 上一步病灶
        'fixHint':      {'type': 'string', 'default': ''},        # 修复指引
        'question':     {'type': 'string', 'default': ''},        # 相关提问
        'queryRaw':     {'type': 'string', 'default': ''},        # 原始越界查询（JSON）
        'requestId':    {'type': 'string', 'default': ''},        # 关联请求
        'status':       {'type': 'string', 'default': '待处理'},
        'remark':       {'type': 'string', 'default': ''},
        'userName':     {'type': 'string', 'default': '系统'},
    },
    'indexes': [
        {'keys': {'status': 1, 'createdAt': -1}},
        {'keys': {'category': 1, 'createdAt': -1}},
    ],
    **_SYS_RW,   # read/write 均限 internal
}
```

### 4.2 统一写入辅助

```python
# server/app/services/auto_feedback.py
async def _write():                       # 必须 async def：run_as_internal 用 iscoroutinefunction 判断
    return await store.insert('AutoFeedback', doc)
try:
    await store.run_as_internal(_write)   # 绕过角色权限，内部上下文写库
except Exception as e:                    # 告警本身失败不击穿调用方，只记 `auto_feedback_fail` 日志
    log('error', 'auto_feedback_fail', error=str(e), category=category, trigger=trigger_point)
```

## 6. 实测与缺陷记录

| 项 | 结果 |
|---|---|
| 静态自检 | `py_compile` 4 文件零错；AutoFeedback 注册断言通过 |
| 部署回归 | 服务 online（mem 6.9→75.6MB，uptime 增长），curl 127.0.0.1:8000 有响应 |
| 写入链路 | `INSERTED AFMTNR6RNPS2IC` → `READBACK`（userName 默认补全"系统"）→ `REMOVED {deletedCount:1, archivedCount:1}` |
| 缺陷 1 | 远程 qa_service 早已引用 `auto_feedback` 模块但缺文件，致服务重启循环 68 次；补齐后稳定 |
| 缺陷 2 | `run_as_internal(lambda: store.insert(...))` 因 lambda 非协程函数，`iscoroutinefunction` 判否，**insert 从未 await、反馈不落库**；改 async 内层函数修复 |

## 7. 禁止事项

❌ 禁止对同机其他项目账号（coen-user / ecs-user）服务做任何操作
❌ 禁止把 AutoFeedback 加入 `BUSINESS_MODELS`（AI 只读白名单）
❌ 禁止用手动 `store.insert` 直写 AutoFeedback（必须走 `record()` 的 internal + 日志兜底）
❌ 禁止定义新的反馈类型 category 枚举之外的取值（guard/fallback/input）
❌ 禁止删除/泄出 `.env` 或含密码的临时脚本

## 8. 注意事项

1. `run_as_internal(fn)` 只 await `iscoroutinefunction(fn)`——传入必须是 `async def`，不能是返回协程的 `lambda`
2. `record()` 内部已自吞异常并写 `auto_feedback_fail` 日志，调用方无需再 try/except
3. mongo-store 读取时自动补默认值，写入传最小数据（不传 userName 也会读回"系统"）
4. 本期只通 server 端告警落库；前端「自动反馈列表」与 preheat/空结果/P1 埋点为 P1，未纳入
