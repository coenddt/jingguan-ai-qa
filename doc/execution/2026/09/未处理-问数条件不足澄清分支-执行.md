# 问数条件不足澄清分支 执行文档

> 日期: 2026-09-05
> 设计依据: 本次对话确认的方案（B 为主 + A 兜底，均启用）
> 性质: 代码执行文档（AI 照此执行）

## 1. 目标（验收标准）

1. 用户在问数时条件不足，后端不再静默产出兜底查询，而是产出追问文案并中断，不执行查询。
2. 追问以 `done` 事件返回（resp 携带 `clarify` 字段），前端渲染独立「澄清」卡片；消息仍落库可回溯。
3. A（生成前意图门）与 B（生成后完整度校验）两类触发条件都命中时均正确走到澄清分支且不双次追问。

## 2. 涉及端 × 角色

| 端 | 是否涉及 | 角色 | 说明 |
|---|---|---|---|
| server | 是 | 后端编排 | qa_service.py 接入澄清分支 |
| web-front | 是 | 前端 | QaAskResp 加 clarify；AiCard 渲染澄清卡片 |

```python
"""场景③ 生成前意图门：判断问题条件是否充分（A 兜底；纯函数）"""

PARAMS = {'temperature': 0.1, 'json': True, 'retries': 0}

SYSTEM_TMPL = (
    '你是问数意图校验器。判断用户问题是否给出了足够明确的查询条件'
    '（切片维度如年份/经营单元/行业/产品线/阶段/风险等级，以及度量）。
    条件充分则只输出 JSON：{"need_more_info": false, "question": ""}；
    条件不足或过于模糊，则输出 {"need_more_info": true, "question": "一句针对性追问"}。
    追问需具体、可答，给出可选值。只输出 JSON，不要多余文字。'
)


def build(variables: dict) -> list[dict]:
    question = variables['question']
    return [
        {'role': 'system', 'content': SYSTEM_TMPL},
        {'role': 'user', 'content': f'可用切片维度：年份(2025/2026)、经营单元、行业、产品线、阶段、风险等级\n问题：{question}'},
    ]
```

### 4.2 新增 `server/app/services/query_clarify.py`

```python
"""条件完整度校验（B，纯函数，禁 IO）：基于 schema 判定 LLM 产出查询是否缺必要条件"""
from app.models.registry import MODEL_TABLE

# 统计/目标类模型必须显式指定年份口径，否则结果口径不明
_REQUIRED_YEAR_MODELS = {
    'ReportOverall', 'ReportProduct', 'ReportSolution',
    'ReportIndustry', 'ReportKeyUnit', 'GoalLedger',
}


def completeness_issues(query: dict) -> str | None:
    """返回需澄清的追问文案；条件充足返回 None。query 须为已过守卫的 checked 模板。"""
    model = query.get('model')
    cond = query.get('condition') or {}
    # 顶层字段条件是 topic 键（非 $ 前缀）
    topic_keys = set(k for k in cond if not k.startswith('$'))
    if model in _REQUIRED_YEAR_MODELS and 'year' not in topic_keys:
        return '请补充查询年份（可选 2025、2026），例如「2026年各经营单元达成情况」。'
    if not topic_keys:
        return '问题条件不足：请补充查询维度或范围（如年份、经营单元、行业、产品线）。'
    return None
```

### 4.3 修改 `server/app/services/qa_service.py`

- 新增澄清 resp 构建助手（async，供 A/B 分支共用）：

```python
async def _build_clarify_resp(session: dict, tracker: StepTracker, model_conf: dict,
                              t0: float, tokens: int, clarify_text: str) -> dict:
    return {
        'session_id': session['_id'],
        'steps': tracker.out(),
        'findings': [], 'columns': [], 'rows': [],
        'stats': {'count': 0, 'avg': 0, 'max': 0, 'max_of': '-', 'min': 0, 'min_of': '-'},
        'chart': None,
        'text': clarify_text, 'follow_ups': [],
        'clarify': clarify_text,
        'query_source': None, 'truncated': False, 'row_count': 0,
        'meta': {
            'elapsed_s': round(time.monotonic() - t0, 2), 'tokens': tokens,
            'model': model_conf['name'], 'modelName': model_conf.get('modelName', ''),
            'platform': model_conf['platform'],
        },
    }
```

- ask_stream 中 A 门（在 `if rows is None:` 块内、`query_gen` 调用之前插入，软门不外抛）：

```python
        if rows is None:
            # —— A：生成前意图门（软门；异常不阻断，直接走 query_gen）——
            intent_q: str | None = None
            try:
                intent, _ret = await llm_client.invoke('intent_gate', {'question': question}, model_conf)
                if intent.get('need_more_info'):
                    intent_q = intent.get('question') or ''
            except Exception:
                intent_q = None
            if intent_q:
                tracker.done(1, f'问题条件不足，已追问澄清：{intent_q}')
                yield _step_ev(tracker, 1)
                resp = await _build_clarify_resp(session, tracker, model_conf, t0, tokens, intent_q)
                await _save_messages(session, question, resp, user_name)
                saved = True
                yield {'type': 'done', 'data': resp}
                return
```

- ask_stream 中 B 门（在 LLM 重试循环 `checked = verify(q)` 通过后、`query_executor.run` 之前插入）：

```python
                    checked = verify(q)
                    issues = completeness_issues(checked)
                    if issues is not None:   # —— B：生成后完整度校验（硬门）——
                        tracker.done(2, f'查询缺少必要条件，已追问澄清：{issues}')
                        yield _step_ev(tracker, 2)
                        resp = await _build_clarify_resp(session, tracker, model_conf, t0, tokens, issues)
                        await _save_messages(session, question, resp, user_name)
                        saved = True
                        yield {'type': 'done', 'data': resp}
                        return
                    tracker.done(2, ...)  # 原有守卫通过文案
```

> 注：B 门放在 guard 通过后、执行前；缓存命中路径（exact_cache）为历史已验证模板，不套 B 门。

## 8. 注意事项

1. A 门为 LLM 判定，属软门：调用异常时必须回落到正常 query_gen，绝不硬失败。
2. B 门基于 schema 确定性判定，为硬门：命中即澄清并 return，不再执行查询。
3. `_save_messages` 后必须把 `saved` 置 True，避免异常处理器二次留痕。
4. 澄清 resp 的 `text` 即澄清文案，落库内容 == 前端 content，可回溯。
5. 前端 AiCard 澄清卡不渲染 AiSteps/报告块；引用既存类名（`.qa-ai-msg/.qa-ai-card/.mod-body/.dot-li`），不新增 CSS。
