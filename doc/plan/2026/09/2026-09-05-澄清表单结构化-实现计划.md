# 问数「澄清表单」结构化升级 — 实现计划

> 日期: 2026-09-05
> 承接: `doc/execution/2026/09/未处理-问数条件不足澄清分支-执行.md`（纯文本版 7/7 已完成，本次在其上做结构化升级）

## Context

当前「问数条件不足」澄清分支只返回**纯文本**追问文案（[AiCard：56-68](file:///F:/独立开发者/项目/AI创新中心项目/web-front/src/features/qa/AiCard/index.tsx#L56-L68) 渲染一行文本卡）。用户希望升级为**结构化表单**，提示用户选择缺失的必要参数，支持单选/多选/输入，提交后补全条件重新问数。

用户已拍板三项设计：

1. 表单字段+选项由 **schema 确定性生成**（选项取自 `DIM_ENUMS` 真实枚举）——A门命中无 model 给通用维度集，B门命中有 model 按目标模型 schema 精确给出缺字段。
2. 提交反馈 = **拼成完整自然语言问题重问**，复用现 `useAsk(q)` 全链路。
3. **对象优先 + 文本回退**：`clarify` 升级为 `{text, question, fields}` 对象；新前端渲染表单，纯字符串维持现有文本卡（兼容老会话与软门回退）。

## ClarifyForm 结构

```ts
ClarifyField { key: string; label: string; type: 'radio'|'checkbox'|'select'|'input';
               required?: boolean; options?: string[]; placeholder?: string }
ClarifyForm  { text: string; question: string; fields: ClarifyField[] }
```

type 映射（后端 `_field_type`）：`year`(2项)→radio；`customer`→input；其他维度 `len(options)<=12`→checkbox（industry=9），`>12`→select（unit=21）。`required` 仅 year。

## 改动清单

### 后端

- **`server/app/services/query_clarify.py`**（保持纯函数、禁IO）：

  - 新增 `DIM_LABELS`（year=年份/unit=经营单元/industry=行业/productLine=产品线/stage=阶段/riskLevel=风险等级/customer=客户）、`MULTI_SELECT_THRESHOLD=12`、`_field_type(key, opts)`、`build_clarify_fields(available_dims, model=None)`（model 给定时过滤 `MODEL_TABLE[model]['fields']`，label 优先 `FIELD_COMMENTS`）。

  - `completeness_issues` 返回从 `str|None` → `dict|None`：新增 `missing_dims(query)` 判缺失字段集（触发条件与现网一致：`_REQUIRED_YEAR_MODELS` 缺 year → `['year']`；无任何 topic 键 → 该模型全部 `DIM_ENUMS` 字段）；命中返回 `{'text':..., 'fields': build_clarify_fields(dims, model)}`。

- **`server/app/agent/prompts/intent_gate.py`**：SYSTEM\_TMPL 增加 `dimensions` 输出字段（条件不足时 `["year","unit",...]`，只可从年/单元/行业/产品线/阶段/风险等级选；拿不准列全）。

- **`server/app/services/qa_service.py`**：

  - import `build_clarify_fields`、`DIM_ENUMS`。

  - A门命中处：`dims = [d for d in intent.get('dimensions',[]) if d in DIM_ENUMS]`；为空则 `dims = list(DIM_ENUMS)`（通用维全集，不含 customer）；构造 `form={'text':intent_q,'question':question,'fields':build_clarify_fields(dims,None)}`。软门语义不变。

  - B门命中处：`issues=completeness_issues(checked)`，`form={'text':issues['text'],'question':question,'fields':issues['fields']}`。

  - `_build_clarify_resp`：`clarify` 参数支持 `str|dict`，`text = clarify if str else clarify['text']`；`resp['clarify']=clarify`（对象或字符串）。`_save_messages` 的 `content=resp['text']` 不变（可回溯），aiMeta 自动持完整对象。

### 前端

- **`web-front/src/types.ts`**：新增 `ClarifyField`/`ClarifyForm`；`QaAskResp.clarify?: string | ClarifyForm`。

- **新增** **`web-front/src/features/qa/AiCard/ClarifyForm.tsx`**：自持 state（`selected: Record<key,string[]>` + `inputs: Record<key,string>`），daisyUI 控件（radio/checkbox/select multiple/input），提交=校验至少一项非空 → `useAsk(buildFullQuestion())`，空提交 Snackbar 提示；取消按钮收起。

  - **拼词规则**（`buildFullQuestion`）：year 单选 → 值作年份前缀嵌句首（`"2026"→"2026年"+原句`）；多选 checkbox/select → `"{label}为{v1}、{v2}"` 顿号并列；input → `"{label}为{value}"`；整体 = year 前缀 + 原句 + 其余各维以"，"串联。word取 DIM\_ENUMS 值，天然命中守卫白名单，query\_gen 易解析为 `$eq/$in`。

- **`web-front/src/features/qa/AiCard/index.tsx`**：澄清早返回块改分支——`typeof resp.clarify === 'string'` 维持文本卡，否则 `<ClarifyForm form={resp.clarify} />`。

## 边界与禁止（沿用既有执行文档 §7）

- 缓存命中(exact\_cache)路径不套表单；不新增 SSE 事件类型（仍 done+data.clarify）；不新增前端数据接口（选项随 clarify 下发）；A门仍软门（异常回落 query\_gen，dimensions 异常回落通用维全集）。落库 content=text。

## 测试方案（云端验证，遵循 testing-rules）

1. **后端 py\_compile + 模块加载**：`query_clarify` 新增函数、`intent_gate` 模块。
2. **三类控件生成**（服务端 `.venv` 直测 + curl 问数）：
