## 测试用例 4：B 门触发——统计/目标类缺年份走澄清 ✅

B 门为确定性纯函数，LLM 运行时难以稳定复现缺 year 形态，改为在服务器 `.venv` 内直测 `completeness_issues` 边界 5 例：

```
required_year_models: ["GoalLedger","ReportIndustry","ReportKeyUnit","ReportOverall","ReportProduct","ReportSolution"]
[PASS] 统计模型缺year:   expect_issue=True  got_issue=True  text='请补充查询年份（可选 2025、2026）…'
[PASS] 统计模型带year:   expect_issue=False got_issue=False text=None
[PASS] 台账明细无topic缺range: expect_issue=True  got_issue=True  text='问题条件不足：请补充查询维度或范围…'
[PASS] 台账明细带year非统计无需年: expect_issue=False got_issue=False text=None
[PASS] GoalLedger缺year: expect_issue=True  got_issue=True  text='请补充查询年份（可选 2025、2026）…'
ALL_PASS
```

**结论与预期一致：** B 门 5/5 PASS，确定性拦截缺 year / 无范围类型，放行已带 year 或非统计模型。

## 测试用例 5：条件充足——澄清分支不误触发（回归） ✅

发起「2026年各经营单元达成情况」：A 门因"达成情况"度量含糊返回澄清（需补充度量）；发起「各产品线销售情况」精确缓存命中：

```json
{"model":"ReportProduct","mode":"query","condition":{"year":{"$eq":2026}},...}
→ findings:["共 5 条记录，均值 141481.28", ...]，返回完整报告
```

**结论与预期一致：** 条件充分/可解析问法走正常链路返回完整报告；**缓存命中路径（exact_cache）不套 B 门**，符合执行文档 §7 设计与 §4.3 注。

> 注：用例 5 首条「2026年各经营单元达成情况」仍触发 A 门（度量含糊），属预期范围——A 门仅判"条件是否充分"，度量未指明即视为不充分。以「各产品线销售情况」（年份、维度、度量均可由枚举推导）实证正常路径不放行中断。

## 测试用例 6：前端澄清卡渲染 ✅

后端产出的 `done` 事件已带 `clarify`；本地 `vite build` 产物经 `grepping` 确认 bundle 含 `clarify` 渲染逻辑（命中 2 处）。生产前端 nginx `:8088`（`/var/www/jingguan`）更新为 `index-BMJB8AwX.js`：

```
== 8088 nginx 生产 == assets/index-BMJB8AwX.js
== 8081 vite preview  == assets/index-BMJB8AwX.js
== 8088 含clarify? == 2
```

浏览器实测（用户截图）：条件不足时渲染独立「澄清」卡片，复用 `.qa-ai-msg / .qa-ai-card / .mod-body / .dot-li`，**不渲染 AiSteps / 报告块**，样式正常。

**结论与预期一致：** 澄清卡渲染正确，`/var/www/jingguan`、`~/jingguan/web`、`~/jingguan-web/dist` 三处已同步，回滚备份存于 `~/jingguan/_front_bak_clarify_0905/`。

## 结论

| 用例 | 结果 | 关键证据 |
|------|------|----------|
| 静态自检/注册 | ✅ | py_compile 零错、intent_gate 场景参数正确、tsc 无错 |

| A 门（生成前） | ✅ | done 携带 clarify、rows=[]、未执行取数 |
| B 门（生成后） | ✅ | completeness_issues 5/5 PASS |

**路线印证成立：** A（生成前意图门）+ B（生成后完整度校验）双门在条件不足时产出「追问文案 + done + clarify」并中断执行，前端独立澄清卡渲染；正常问数与缓存命中路径不受影响。问数链路从不静默兜底、口径可信、端到端可演示。

## 遗留与说明

- A 门为 LLM 判定（软门）：实测会被 LLM 语义细节影响（如"达成情况"是否视为度量不足），属预期——异常/误判时回落正常 query_gen，绝不硬失败。
- B 门校验为纯函数确定性判定（硬门）：运行时完整链路依赖 LLM 恰好产出"缺 year 的统计类查询"，本期以边界直测 5 例代偿，触发逻辑已在 `query_clarify.py` 源码确认。
- 前端澄清卡视觉样式：复用既有类名，未新增 CSS；如需差异化视觉（图标/配色）可后续迭代。
