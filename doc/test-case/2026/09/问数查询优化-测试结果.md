## 测试用例 4：强模糊命中分级（tier=warm）✅

近义问法 B=`2026年解决方案收入按行业统计数据看看`（对已缓存问法 A 略改）。

```
ask_tier      | tier=warm candidates=1 concurrency=1 best_score=0.794
ask_preheat   | ok=True elapsed_s=0.56 cache_hit=2688 cache_miss=66
ask_candidates| generated=1 passed=1 cache_hit=2432 cache_miss=457
ask_done      | total_ms=6127 retries=0 query_source=llm
```

**结论与预期一致：** `best_score=0.794≥0.75` → warm，1 候选即过守卫。

> 过程说明：最初 probes `各产品线今年收入排名看看` 与缓存问法相似度仅 ~0.31，`best_score=0.0` 被判 cold——判定器工作正常，是 probes 选得太远。

## 测试用例 5：前缀预热 + 缓存命中 ✅

冷问 3 候选时（用例 3 首问）：

```
ask_preheat   | ok=True elapsed_s=0.52 cache_hit=2688 cache_miss=66
ask_candidates| generated=3 passed=3 cache_hit=8064 cache_miss=222   # 8064 = 3×2688
```

conclusion 调用：`llm_call scenario=conclusion elapsed_s=1.62 cache_hit=128 cache_miss=302`

**结论与预期一致：** 预热请求与候选并发落地（`elapsed_s=0.52` 未占关键路径）；3 候选各命中共享 system 前缀 2688，总 8064 按缓存价计费。

## 测试用例 6：回归——串行兜底可用 ✅

代码审阅：`qa_service` 在自然语言分支的候选全失败（`checked_list` 空）时进入既有串行错误回传修正分支，未删旧兜底。

**结论与预期一致：** 并行候选择优未破坏「全败走串行重试」底线。

| 用例 | 结果 | 关键证据 |
