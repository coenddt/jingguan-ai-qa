# 经管之星·AI问数助手 部署步骤文档

## 核心概念

一句话：**代码在本地改，产物上传** **`<user>`** **账号服务器，MongoDB 存数据，FastAPI 被 pm2 托管，nginx 出网（静态 + 反代 + 登录校验）**。首次部署走全量，日常迭代走增量。

**服务器信息**：`<user>@<SERVER_IP>`（Ubuntu，sudo 组）；禁止触碰同机其他账号（`coen-user`/`ecs-user`）。

## 服务器资源约束（当前演示机·低配）

当前演示/产品服务器是**低配置、硬盘空间不充足**的弱机，一切部署必须按最小占用规划：

| 约束     | 现状          | 部署应对                                 |
| ------ | ----------- | ------------------------------------ |
| CPU/内存 | 弱配置，并发能力低   | 单实例 + `uvicorn worker=1`；Mongo 不开副本集 |
| 硬盘空间   | **不充足**     | 坚持增量上传，禁整树覆盖；随时查 `df -h`             |
| 对外架构   | 不出网暴露，自用/演示 | 回环部署 + 登录，不做直升机 HA                   |

```bash
# 部署前必查磁盘，低于阈值先清理再上传
df -h | awk '$5+0 >= 85 {print "磁盘已超85%:", $6, $5}'
du -sh ~/jingguan/ ~/.pm2/logs/ /data/mongo   # 三大占用点例行体检
```

> **硬盘铁律**：jinguan 目录、pm2 日志、Mongo 数据是磁盘三大增长点；日志需 rotate，构建产物/备份按需删，不要让磁盘写满（写满会导致 Mongo 只读失败、服务雪崩）。

## 部署资产清单

| 资产      | 本地路径（唯一事实源）       | 服务器路径                                            |
| ------- | ----------------- | ------------------------------------------------ |
| 后端代码    | `server/`         | `~/jingguan/api/`                                |
| 前端源码    | `web-front/`      | -（只传产物）                                          |
| 前端产物    | `web-front/dist/` | `~/jingguan/web/`                                |
| 敏感配置    | -（不入 git）         | `~/jingguan/api/.env`（chmod 600）                 |
| MongoDB | -                 | 系统服务 `mongod-jingguan`，端口 **27018**，库 `jingguan` |
| FastAPI | -                 | pm2 `jingguan-api`，`uvicorn @127.0.0.1:8000`     |
| nginx   | -                 | `/etc/nginx/conf.d/jingguan.conf`                |

> 配置一致性铁律：改配置先改**本地**，再同步服务器；无注释的环境差异一律视为 BUG。

## 首次部署：本地自检

```bash
# 后端：编译 + 模块加载 + 单测（零环境本地跑）
python -m py_compile "$(git ls-files server | grep '\.py$')"
python -c "import app.main"                       # 全链路无导入错
pytest -q                                          # 核心单测全绿

# 前端：TS 类型 + 构建产物可用
cd web-front && npx tsc --noEmit
```

**验证**：本条全过才允许上传。

## 首次部署：MongoDB

```bash
# 服务器端口预检（8000 给 API，27018 给 Mongo；27017 属生活助手严禁占用）
ss -tlnp | grep -E ':(8000|27018)'
# bindIp 回环 + 认证 + 端口 27018；dbPath /data/mongo；systemd 前台运行，不开 fork

# 建库用户（密码用随机强密码，只进 .env）
mongosh --port 27018 jingguan --eval '
  db.createUser({user:"jingguan", pwd:"<强密码>",
                 roles:[{role:"readWrite",db:"jingguan"}]})'

# 常驻 + 生效验证
systemctl enable --now mongod-jingguan
ss -tlnp | grep 27018                              # 只见 127.0.0.1:27018
mongosh --quiet --eval "db.runCommand({ping:1})"   # 无凭据 → 认证报错（授权已生效）
```

`.env` 对应连接串（**`authSource`** **必须带上**，否则 pymongo 默认对 admin 库认证会失败）：

```
MONGO_URI=mongodb://jingguan:<密码>@127.0.0.1:27018/?authSource=jingguan
```

## 首次部署：上传后端

```bash
# 本机 SCP 上传
scp -r server/ <user>@<SERVER_IP>:~/jingguan/api/

# 服务器装依赖（固定 Python 3.11，明确版本勿整棵升级）
cd ~/jingguan/api
python3.11 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt    # fastapi uvicorn[standard] pymongo[async] pydantic-settings openpyxl httpx
```

写 `.env`：`SECRET_KEY / ADMIN_* / MONGO_URI / VOICE_*`（火山 KEY、API Key 等敏感值**只存服务器侧**，本地以占位符 + 来源注释标注）。

**验证**：`python -c "import app.main"` 无错。

## 首次部署：构建并上传前端

```bash
cd web-front && npm run build        # 产出 dist/
scp -r web-front/dist/ <user>@<SERVER_IP>:~/jingguan/web/
```

**验证**：`ls ~/jingguan/web` 见 `index.html`。

## 首次部署：nginx 出网 + 登录

```nginx
# /etc/nginx/conf.d/jingguan.conf（nginx 为共享服务：改前备份、nginx -t 通过后 reload）
server {
  listen 80;
  server_name jingguan.example.com;   # 按实际域名/IP

  root /home/<user>/jingguan/web;
  index index.html;

  # 登录三接口直接放行，否则登录死循环
  location = /api/auth/login   { proxy_pass http://127.0.0.1:8000; }
  location = /api/auth/check   { proxy_pass http://127.0.0.1:8000; }
  location = /api/auth/logout  { proxy_pass http://127.0.0.1:8000; }

  # 其余 /api → auth_request 校验后反代
  location /api/ {
    auth_request /__auth;
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }

  location = /__auth {
    internal;
    proxy_pass http://127.0.0.1:8000/api/auth/check;
    proxy_pass_request_body off;
    proxy_set_header Content-Length "";
    proxy_set_header X-Original-URI $request_uri;
  }

  # 前端 SPA + 未登录兜底跳登录
  location / { try_files $uri $uri/ /index.html; }
}
```

```bash
nginx -t && systemctl reload nginx     # 必须 -t 通过再 reload，验证其他站点不受影响
```

**认证语义**：后端 `check` 验 HMAC 签名 Cookie（24h 过期）→ 有效 200 / 无效 401 → nginx `auth_request` 拦截 → 前端 axios 捕获 401 跳 `/login`。前端不存 token，Cookie `HttpOnly` + `SameSite=Lax`，axios `withCredentials: true`。

## 首次部署：pm2 起 FastAPI

```bash
cd ~/jingguan/api && . .venv/bin/activate
# process.json
# { "apps": [{ "name":"jingguan-api","script":"uvicorn",
#   "args":"app.main:app --host 127.0.0.1 --port 8000",
#   "interpreter":".venv/bin/python","cwd":"/home/<user>/jingguan/api" }] }
pm2 start process.json
pm2 save && pm2 startup               # 开机自启
curl http://127.0.0.1:8000/api/auth/check
```

**验证**：不带 Cookie → 401（证逻辑而非填错）；pm2 日志 `~/.pm2/logs/jingguan-api-*` 无报错。

## 首次部署：首启种子 + 端到端

```bash
pm2 restart jingguan-api               # 触发启动事件：建 schema + 建索引 + 库空灌种子
mongosh --port 27018 -u jingguan -p --authenticationDatabase jingguan
# 查 jingguan 各集合有数据、索引存在
```

浏览器验证 3 项：登录 → 问"2026年各经营单元收入排名柱状图" → 表格 + 图表渲染；再问越界查询（如 `$where` 注入）→ 被守卫拒绝。

## 日常更新：改后端

```bash
# 1) 本地自检
python -m py_compile server/app/**/*.py
# 2) 上传（按改动范围传，避免整树覆盖淹没日志）
scp server/ <user>@<SERVER_IP>:~/jingguan/api/
# 3) 重启 + 校验
ssh <user>@<SERVER_IP> "pm2 restart jingguan-api"
curl http://127.0.0.1:8000/api/auth/check
```

> 大改动部署前先比对版本：`ssh <user>@<SERVER_IP> "grep -n <关键标识> ~/jingguan/api/<文件>"`，防本地与服务器漂移。

## 日常更新：改前端

```bash
cd web-front && npm run build
scp -r web-front/dist/ <user>@<SERVER_IP>:~/jingguan/web/
# 静态资源由 nginx 直出，无需重启；刷新浏览器验证
```

## 日常更新：改配置

```bash
# 先改本地（占位符/注释），再同步服务器
scp .env <user>@<SERVER_IP>:~/jingguan/api/.env && chmod 600
ssh <user>@<SERVER_IP> "pm2 restart jingguan-api"
```

**铁律**：密钥只存在于服务器侧 `.env`；任何配置改动不留未注明来源的本地-服务器差异。

## 回滚

| 场景            | 动作                                                        |
| ------------- | --------------------------------------------------------- |
| 后端回归          | 回滚上次代码版本 → 重新上传 → `pm2 restart jingguan-api`              |
| 前端回归          | 回滚上次 `dist/` → 重新 SCP → 刷新                                |
| Mongo / nginx | 走各自备份：`/data/mongo`、`/etc/nginx/conf.d/jingguan.conf.bak` |

## 禁止事项

❌ 不在本机启动 Mongo/FastAPI 常驻实例（演示只在服务器）\
❌ 不把 `.env`（SECRET\_KEY/管理员密码/Mongo 凭据/火山KEY/API Key）提交入库\
❌ 不对外暴露 MongoDB（仅回环 127.0.0.1）\
❌ 不用 `auth_basic` 替代（无 24h 时效）；登录走后端 Cookie\
❌ 不误碰同机 `coen-user` / `ecs-user` 账号、27017 Mongo、共享 nginx 其他站点\
❌ 不在 `sattc` 旧账号部署或启动服务（残留仅作回滚备份）\
❌ 不保留含密码的临时 SSH 脚本（执行完立即删除）\
❌ 改配置只在服务器偷偷改（首改本地再同步）

## 注意事项

1. **配置一致性铁律**：本地是唯一事实源，改配置先本地后服务器；无注释的环境差异一律视为 BUG
2. **低配 + 盘不足**：本演示机 CPU/内存弱、**硬盘空间不充足**——坚持增量上传、日志 rotate、构建产物与备份按需删；部署前先 `df -h` 查磁盘，写满会致 Mongo 只读失败、服务雪崩
3. **弱机最低配**：Mongo 单实例回环即可，勿开副本集/外网绑定；磁盘与日志定期 rotate
4. **端口归属**：8000（API）/27018（Mongo）是本项目专用；27017 属生活助手严禁占用，新服务端口先确认空闲
5. **nginx 共享服务**：改前备份、`nginx -t` 通过后 reload；`server_name` 按实际定，与 `default_server` 冲突时用独立端口
6. **登录活死循环**：login/check/logout 三个 location 必须放行，否则永远跳登录
7. **401 定位**：分「未登录」还是「接口错误」——`curl` 带/不带 Cookie 对比，看 `pm2 logs` 与 `nginx error.log`
8. **pm2 即 Supervisor**：改后端必 `pm2 restart` 生效；功能验证走 `server-testing` 云端流程（SSH 看日志 + curl 线上端口）
9. **发版门槛**：服务端自检达 B 级（84.7）可合入，上线硬门槛 A 级 ≥90 与覆盖率 ≥90%——上线前先降圈复杂度、补路由层测试
